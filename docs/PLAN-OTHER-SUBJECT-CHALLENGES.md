# แผนเพิ่มโจทย์จากวิชาอื่นใน BREACH / RESPONSE

## เป้าหมาย

ขยายเกมจากห้อง Web Security Awareness เดิม ให้มีห้อง Escape Room สำหรับเนื้อหาจากวิชาอื่น โดยผู้เล่นเลือกห้องตามหัวข้อได้ และแต่ละห้องมีโจทย์เป็นลำดับด่าน

## สิ่งที่ได้จากรายงานอ้างอิง

รายงานอธิบายโครงสร้างระบบ Escape Room ที่มีผู้เล่นเลือกห้อง เล่นด่าน ตอบโจทย์ ขอ Hint เก็บคะแนนและ Progress พร้อมมี Attempt, Achievement และ Leaderboard แนวทางยังระบุความสัมพันธ์ระหว่างห้อง หมวดหมู่ ด่าน โจทย์ และ Hint ไว้ด้วย

รายงานเป็นเอกสารวิเคราะห์และออกแบบระบบ Cyber Escape Room ไม่ได้ให้ชุดโจทย์เฉพาะวิชา Database, Programming หรือวิชาอื่น ดังนั้นโจทย์เพิ่มเติมจะต้องร่างขึ้นใหม่ โดยยึดรูปแบบและ workflow ของเกมตามรายงาน

## ขอบเขตเนื้อหาที่เสนอ

คงห้อง Cybersecurity เดิมไว้ และเพิ่มห้องแยกตามวิชา เพื่อให้หัวข้อไม่ปะปนกัน

### ระยะที่ 1: Database Quest

1. ER Model และความสัมพันธ์ — ระบุ Entity, Cardinality หรือความสัมพันธ์จากสถานการณ์
2. Keys และ Constraints — เลือก PK/FK และข้อจำกัดที่ถูกต้อง
3. Normalization — วิเคราะห์ปัญหาซ้ำซ้อนและจัดรูปข้อมูลให้เหมาะสม
4. SQL Query — อ่านผลหรือเติมเงื่อนไข `JOIN`, `WHERE` และ `GROUP BY`
5. Transactions — วิเคราะห์ผลของการทำรายการและเงื่อนไขที่ควรปฏิเสธ

### ระยะต่อยอด

- Programming Logic: ลำดับคำสั่ง เงื่อนไข และการไล่ค่าตัวแปร
- Data Structures: เลือกโครงสร้างข้อมูลและวิเคราะห์ผลจากการดำเนินการ
- Networking: อ่าน HTTP/DNS และวิเคราะห์ subnet หรือเส้นทางข้อมูล
- Operating Systems: สิทธิ์ไฟล์ Process และการจัดสรรทรัพยากร

## แนวทางนำเข้าเกม

- เพิ่มห้องและโจทย์เป็นข้อมูล seed แยกจากเนื้อหา Cybersecurity เดิม
- ใช้โครงสร้าง Room, Stage, Puzzle และ Hint ที่ระบบมีอยู่
- แต่ละโจทย์กำหนดคำตอบ Hint คะแนน และคำอธิบายหลังตอบให้ครบ
- ให้การตรวจคำตอบ การปลดล็อกด่าน การคำนวณคะแนน และ Leaderboard ใช้ workflow เดิม
- ทำ seed ให้รันซ้ำได้โดยไม่สร้างห้องหรือโจทย์ซ้ำ

## ข้อจำกัดและสิ่งที่จะไม่เปลี่ยน

- ไม่แก้ Prisma schema, API route, route ของหน้าเว็บ, ระบบ Auth หรือ Middleware
- ไม่แก้ตรรกะการคิดคะแนน การตรวจคำตอบ หรือการปลดล็อกด่าน
- ไม่เปลี่ยนห้อง Cybersecurity เดิม
- เนื้อหาโจทย์ใหม่เป็นข้อมูลตัวอย่างเพื่อการเรียนและการสาธิต ไม่เชื่อมต่อหรือแก้ไขระบบภายนอก

## ไฟล์ที่คาดว่าจะเพิ่มหรือปรับเมื่อเริ่มพัฒนา

- เพิ่มไฟล์ข้อมูลโจทย์/ห้องใหม่ เช่น `prisma/subject-content.ts`
- เพิ่ม seed runner แยก เช่น `prisma/seed-subjects.ts`
- เพิ่มคำสั่งเรียก seed ใน `package.json`
- ปรับ `docs/DEMO.md` เพื่ออธิบายวิธีเตรียมและสาธิตห้องใหม่

ยังไม่มีการแก้ไขไฟล์เหล่านี้ในขั้นตอนจัดทำแผนนี้

## แผนทดสอบเมื่อเริ่มพัฒนา

1. รัน seed สองครั้งและยืนยันว่าไม่มีข้อมูลซ้ำ
2. ตรวจว่าห้องใหม่ปรากฏในหน้าเลือกห้อง ขณะที่ห้องเดิมยังอยู่ครบ
3. เล่นโจทย์ผ่าน UI ตั้งแต่เริ่มห้อง ส่งคำตอบผิด/ถูก และตรวจ Hint กับสถานะด่าน
4. ตรวจข้อมูลที่เปลี่ยนใน session, progress, attempts, hint usage และ leaderboard
5. ยืนยันว่า `/target` และเกม Cybersecurity เดิมไม่เปลี่ยน
